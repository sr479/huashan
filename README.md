# 花山节 · 苗族服饰租赁

面向到店取还业务的顾客端与门店管理后台。前后端共享真实数据库；示例服装、订单和插画已明确标记，可用于首次体验。

源码：[sr479/huashan](https://github.com/sr479/huashan) · [版本记录](CHANGELOG.md) · [腾讯云部署与更新说明](docs/腾讯云部署.md) · [微信小程序接入说明](docs/微信小程序.md)

`main` 为可运行主分支，正式发布使用 `vX.Y.Z` 标签。GitHub Actions 自动运行测试、类型检查、生产构建与容器构建；服务器部署由人工选择版本后执行。提交信息默认使用中文。

## 本地运行

要求 Node.js 22.13 或更高版本。项目使用 Node 内置 SQLite，目前 Node 22 会显示 experimental 提示，不影响启动。

```bash
npm ci
npm run setup
npm run dev
```

- 顾客端：<http://127.0.0.1:3000/>
- 管理后台：<http://127.0.0.1:3000/admin>
- 本地管理员账号、随机密码保存在根目录 `.env` 的 `ADMIN_USERNAME` 和 `ADMIN_PASSWORD` 中。该文件已忽略，不应提交、分享或放入静态目录。
- 首次默认导入 6 套示例服装和示例订单；实拍、门店地址、联系电话等需在后台完善。示意插画不代表真实库存。
- 服装、订单、会话、资金流水、设置与审计日志保存在 `data/huashanjie.sqlite`；实拍保存在 `data/uploads/`。
- 开发服务支持前端热更新，WebSocket 复用网站端口；修改服务端后需重启。

## 已实现

顾客端：手机适配、日期/分类/名称筛选、按租期判断可租、详情和月历、尺寸配饰、价格与押金、预计归还/最早预计可租、预约申请、预约回执查询、待确认申请取消、门店信息与租赁指南。

管理端：登录鉴权、经营待办、线上及线下订单、确认和排期冲突检查、租金/押金分别登记、取衣、续租、归还验收、押金退还和扣款、结算、清洗/维护、服装实拍上传及上下架、7/14 天排期、流水 CSV 导出、门店设置、操作审计。

支付为**线下收退登记**，没有接入微信支付、短信或自动扣款。管理员通过实际完成的收付款记录账目。

## 微信小程序

微信小程序顾客端源码位于 `miniapp/`，提供公开选衣、价格/档期、预约和回执查询，继续调用现有 API 和管理后台，不使用微信支付、微信登录或云开发。运行 `npm run miniapp:prepare` 后可准备微信开发者工具项目；正式发布仍需合规主体与类目、备案及 HTTPS 合法域名。已接入注册账号“苗衣集”，通过微信开发者工具上传 `0.1.0` 开发版本，对应 Git 标签 `miniapp-v0.1.0`，尚未正式发布。当前已覆盖接口与页面逻辑测试，检查了目录、详情、档期、预约表单和查询页。账号持有人已确认手机开启开发预览调试后可加载云端服装目录；完整预约流程仍待真机验收，详见[接入说明](docs/微信小程序.md)。

## 业务规则

1. 一个独立服装编号对应一套实物，同款的多套衣服需要分别建档。
2. 按自然日计租，取衣日和还衣日均计费，单笔最多 90 天，支持预约未来一年内的取衣日期。
3. 待确认申请不锁库存；店主确认时使用 SQLite `BEGIN IMMEDIATE` 事务重新检查。租期及其后的清洗时间不可与其他已确认、出租或清洗占用重叠。
4. 价格、押金和清洗天数在预约创建时保存快照；之后修改服装价格或默认清洗规则不会改变已有订单。
5. 取衣前需要确认预约、收足租金和押金，且实物处于在店待租状态。
6. 归还后进入清洗状态，实际完成检查后才恢复在店待租。预计清洗日期已过却未完成时继续锁定。超过门店设定的北京时间还衣截止时间即标记逾期，并锁定后续档期；实际归还或登记续租前不会自动回库。已过归还截止时间的租期不能新增或确认。
7. 续租按原日租价计算，并再次核对后续预约和清洗冲突。
8. 押金独立于收入；扣款计入收入，退租金抵减收入。禁止超收、超退，退款和扣款须填写说明。押金结清后才能完成订单。
9. 取消订单只释放该订单的排期，不改变实物的清洗/出租状态；已有款项仍需另行登记退款。
10. 公开接口不返回其他顾客信息。预约回执需要同时匹配随机预约编号与手机号，管理接口需要有效会话。

金额以整数“分”存储，日期按北京时间处理。当前适合单店、单服务器部署，后续多店或多实例部署可迁移至 PostgreSQL 和对象存储。

## 腾讯云部署

以下是可直接使用的部署配置；目标实例的运行状态、域名和备案状态应在部署时核对。

已有服务器同时运行其他业务时，先查看[共用服务器部署方案](docs/腾讯云部署.md)。下面的 Caddy 配置适用于独立实例或 80/443 确认空闲的服务器。

1. 将项目放到腾讯云服务器 `/opt/huashanjie`，安装 Docker 与 Compose 插件。
2. 复制 `deploy/production.env.example` 为服务器根目录 `.env`，设置真实随机管理密码、账号和域名。不要沿用本地体验密码。
3. 核对域名的备案接入状态，再将 `huashanjie.top` 的 A 记录指向该服务器。允许入站 80、443 端口；应用的 3000 端口无需暴露公网。
4. 执行 `docker compose up -d --build`。Caddy 会在域名解析正常后申请并续期 HTTPS 证书，HTTP 自动转 HTTPS。
5. 登录 `https://huashanjie.top/admin`，录入实际服装、上传实拍、填写电话、地址、营业时间、备案号和租赁规则。Compose 的生产配置不会导入示例数据。
6. 测试顾客预约、确认、收款、取衣、归还、清洗与押金结算，再正式对外使用。

`compose.yaml` 将 SQLite、上传图片保存在持久卷 `store_data`，证书保存在独立持久卷。部署时只运行一个应用实例。`TRUST_PROXY=true` 仅用于该配置中唯一的可信 Caddy 反向代理，不应在直接暴露应用端口时开启。

应用不依赖 Google 字体、外部图片或第三方 CDN，服装实拍由本机存储提供。

### 临时云端验收

`deploy/compose.preview.yaml` 提供独立的 `huashanjie-preview` 项目、测试数据卷和示例服装，应用仅绑定 `127.0.0.1:3400`，限用半个 CPU、384 MiB 内存。测试环境应使用单独生成的后台密码，不要录入真实顾客资料。

将配置复制到服务器 `/opt/huashanjie-preview/compose.yaml`，在该目录的私有 `.env` 中设置 `PREVIEW_ORIGIN=https://<公网IP>:8443`、`ADMIN_PASSWORD`、`APP_IMAGE_TAG`。使用已经校验版本的应用镜像启动；不要在共用实例编译镜像。

`deploy/nginx.preview.conf.example` 使用有效 IP 证书，顾客端直接访问，管理页面与管理 API 保留独立 HTTP 访问密码和应用登录验证；初始仅监听回环地址。开放测试前先核对顾客页面、目录及图片无密码可访问，管理页面和管理 API 无入口密码时返回 401、带入口密码后后台登录退出正常；再核对安全 Cookie、测试范围、未绑定域名、云防火墙和到期时间。

临时测试入口应设置自动到期任务，调用 `deploy/stop-preview.sh` 停止独立容器、撤下测试 Nginx 入口并保留测试数据。该脚本要求复制到 `/opt/huashanjie-preview/stop-preview.sh`。测试数据不合并到正式库；测试入口不用于正式对外经营，正式开放前仍需核对相应备案要求。

## 备份与恢复

```bash
# 本地
npm run backup

# 服务器 Docker 部署
docker compose exec -T app npm run backup
```

备份脚本使用 SQLite `VACUUM INTO` 生成一致的数据库快照，同时复制实拍目录，写入 `data/backups/<时间戳>/`，不会删除旧备份。可设置 `BACKUP_DIR` 指向额外磁盘；应另存异地副本。

`deploy/backup.service`、`deploy/backup.timer` 提供北京时间每日 03:00 的 systemd 备份配置。先核对目标实例是否已经启用；尚未配置时，确认部署路径与 Docker 路径后安装到 `/etc/systemd/system/`，再启用 `huashanjie-backup.timer`。

恢复时先停止应用，将选定备份的数据库和 `uploads/` 还原至持久化数据目录，保留原数据副本，并删除目标库旧的 `-wal`、`-shm` 附属文件后再启动。用管理员后台核对服装和最近订单。

## 账号和数据维护

修改 `.env` 的管理员账号或密码并重启后，程序会更新密码哈希并撤销所有旧会话。管理员会话有效期 8 小时，Cookie 使用 HttpOnly、SameSite Strict，HTTPS 部署启用 Secure。

服装下架保留历史订单及流水。当前没有不可恢复的业务数据删除功能。要从本地示例环境开始真实经营，建议保留体验数据备份，创建新的数据目录并设置 `SEED_DEMO=false`，避免误用示例订单。
