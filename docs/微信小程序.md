# 花山节微信小程序接入

首版采用微信原生小程序；顾客无需注册账号，可看衣服、查价格和档期、提交预约，到店取还和付款。管理后台继续使用现有网页，服装、订单、租金押金和 SQLite 数据库保持同一套，不增加云开发环境或支付商户依赖。

## 先准备什么

1. **小程序账号与 AppID**：在[微信公众平台](https://mp.weixin.qq.com/)核实或注册“小程序”。微信开放平台账号、移动应用列表不等于已注册小程序。提供小程序名称、AppID、主体类型即可；首版不需要 AppSecret、密码、验证码或上传私钥。
2. **主体与类目**：按实际的服装租赁业务核实微信后台可选类目及资质。没有营业执照时，先核实是否可用个人主体提供该服务，再决定是否办理个体工商户；不能以其他类目或他人的主体代替真实经营信息。
3. **门店资料**：门店电话、微信号、地址、营业时间、准确的七天营业日期、取还时间、租赁与押金规则，以及隐私问题的联系渠道。可继续在现有后台填写。
4. **真实服装资料**：每套的独立编号、名称、分类、尺码/尺寸、配饰、日租价、押金、实拍，以及已经被租走或预约的日期。可在现有后台逐套录入，不需要重复提供两份。
5. **正式发布配置**：完成小程序备案；自建境内后端所用域名需要完成对应备案并配置有效 HTTPS，将其添加为小程序 `request` 与 `downloadFile` 合法域名。不能把临时 IP 测试入口直接作为正式小程序后端。

实名材料和营业执照等由账号持有人直接提交给微信/腾讯云；不应放入源码或聊天。管理员扫码、人脸核验、短信验证与付款由账号持有人完成。后台的《用户隐私保护指引》需按真实运营主体、收集的称呼/手机号/预约信息、用途、保存安排和联系方式填写，与页面说明一致。

## 本地准备与联调

要求现有项目依赖已安装，Node.js 版本与主项目一致。

```bash
npm run miniapp:prepare
npm run dev
```

准备脚本仅在文件缺失时复制配置，不覆盖已有配置。生成的 `miniapp/config.js`、`miniapp/project.config.json` 与开发者工具私有设置均在 Git 忽略范围内。仓库中的配置示例只使用开发地址和游客 AppID 占位值。

在[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)导入本项目下的 **miniapp 目录**。未注册账号时可先尝试工具提供的测试号/游客模式；哪些预览与分享能力可用，以工具提示为准。获得真实账号后，将本地 `project.config.json` 的 `appid` 改为自己的 AppID。

开发者工具中使用默认 `http://127.0.0.1:3000` 联调，需要在工具的本地开发设置中选择“不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书”。这一设置仅用于本机调试；真机上的 `127.0.0.1` 指手机自身。真机调试需设置手机可访问的测试后端，正式版必须使用有效 HTTPS 域名并恢复域名校验。

`config.js` 示例：

```js
module.exports = {
  apiBaseUrl: 'https://API_DOMAIN.invalid', // 改为实际已备案的接口域名，不带 /api
  allowLocalDevelopment: false,
};
```

小程序运行时会读取 `envVersion`；只有 `develop` 且显式启用本地开发时才允许 HTTP。默认 `trial` 与 `release` 均拒绝 HTTP、IP、未配置域名、路径前缀和非 443 端口。为受邀成员内测，可以仅在忽略的本机配置中显式启用 `allowTemporaryTrial`，并设置含时区的 `temporaryTrialExpiresAt`；只有未到期的 `trial` 才允许手机可达的 HTTPS 测试入口，拒绝回环、内网地址及占位域名。例外不适用于 `release`。配置校验不能替代微信平台对备案、证书和合法域名的检查，体验成员仍须按开发测试方式核对手机端域名校验设置。

## 微信版本管理与朋友内测

代码版本保存在 GitHub；微信后台的版本管理用于管理已上传的开发版、体验版及线上版。小程序版本号单独记录在 `miniapp/package.json`，不随主站版本自动变化；首个内测版本为 `0.1.0`。

1. 使用注册得到的小程序 AppID 接入本地 `project.config.json`，重新打开开发者工具项目。AppID 不使用测试号的旧值，AppSecret 无需提供。
2. 完成本地测试与构建，核对模拟器、手机预览及目标测试后台；保存 Git 提交。
3. 在微信开发者工具点击“上传”，填写与 `miniapp/package.json` 一致的版本号和本次改动摘要。记录上传成功的代码提交，使用 `miniapp-v0.1.0` 等 Git 标签标识实际上传版本；不能把预览码生成视为后台上传成功。
4. 由管理员进入微信公众平台的“开发管理 → 版本管理”，在开发版本中找到刚上传的版本，设置为体验版。在“成员管理 → 体验成员”添加朋友微信号，再把体验二维码交给受邀成员。
5. 本阶段仅内测；不点击“提交审核”或“发布”。朋友按实际权限扫码，检查服装、价格档期、预约提交、后台确认和查询回执。每次更新上传新的版本号，例如 `0.1.1`，并重新选择对应体验版本。

当前仍使用独立限时云端示例测试后台，不能把体验版上传成功当作接口已可用。仅该项目本机忽略的配置启用了受邀体验版 HTTPS 测试例外，截止北京时间 2026 年 10 月 24 日 13:45，与现有服务停止时间保持一致；配置开关不会延长服务器服务时间。到期需停止使用或另行准备测试服务。微信后台的账号权限、体验版可用性及额外资料要求，以实际后台提示为准。

2026 年 10 月 21 日已接入注册账号“苗衣集”，微信开发者工具已识别该名称和注册 AppID，并显示未发布；`0.1.0` 上传得到“代码上传成功”提示，对应提交 `45f7ee5` 和标签 `miniapp-v0.1.0`。上传备注记录了代码提交与测试截止时间。完整上传记录和界面截图保存在本机 Git 忽略的 `data/deployment/`，不包含 AppSecret。微信后台的“设为体验版”和体验成员名单仍由管理员在官方页面操作，不能把代码上传成功等同于朋友已获得访问权限。

### 手机开发预览连接失败

模拟器的本地设置不等于手机已启用调试。临时 IP 测试服务即使可以在浏览器打开，也可能被手机小程序的域名校验拦截。应先读取错误类型，再由账号持有人决定是否仅对该开发预览启用手机侧调试；不能以浏览器能访问或模拟器成功代替真机验收。该方式只用于开发联调，正式发布仍需合法域名和有效证书。参见[腾讯云网络调试说明](https://intl.cloud.tencent.com/zh/document/product/1219/61745)。

本次真机连接失败已通过诊断提示定位为域名校验拦截。账号持有人在手机右上角“…”的开发调试菜单中手动开启该开发预览调试，重新扫码后已确认可以看到服装。测试结束应关闭此调试设置；不应将该做法用于正式发布。

开发版及明确启用临时测试配置的体验版，网络失败提示包含诊断码：`NET_DOMAIN` 为域名校验、`NET_TLS` 为安全连接、`NET_TIMEOUT` 为超时、`NET_OFFLINE` 为无网络、`NET_CONNECT` 为连接失败，`NET_UNKNOWN` 表示尚未归类。诊断码不包含原始 URL、查询参数或顾客信息，正式版不展示开发诊断。预约写请求失败时始终提示核实结果，不会自动重新提交。

手机必须访问云端或同一局域网中手机可达的后端；`127.0.0.1` 指手机自身。本机后台、独立云端测试后台和正式后台使用各自的数据目录，不会自动同步本机录入的服装。手机预览应核对配置连接的服务，并在对应环境的管理后台维护测试数据。

## 页面与接口

| 页面       | 行为                                               | 复用接口                                             |
| ---------- | -------------------------------------------------- | ---------------------------------------------------- |
| 首页       | 日期、分类、名称筛选，显示价格、当前状态及预计归还 | `GET /api/catalog`                                   |
| 服装详情   | 实拍、尺寸/配饰、押金、月历、所选租期核对          | `GET /api/catalog`、`GET /api/garments/:id/calendar` |
| 预约       | 手动填写称呼、手机号和备注，阅读规则后提交         | `POST /api/bookings`                                 |
| 查询与回执 | 预约号及手机号匹配，查看最新确认状态               | `POST /api/bookings/lookup`                          |
| 信息说明   | 预约信息用途、联系门店与租赁规则                   | 复用门店设置                                         |

小程序请求不发送管理 Cookie、管理密码或微信密钥，不调用管理接口。原后台鉴权与来源检查保持原状；原生 `wx.request` 的无 Cookie 请求可使用现有公开接口，不需要开放管理接口的跨域权限。

预约由服务器重新校验库存并计算金额，创建后为待确认，店主确认时事务检查冲突。顾客端提交前刷新价格及规则，变化时要求重新核对；防止连续点击产生多笔预约，网络中断时不自动重发写操作。回执通过内存传递，不把手机号放入 URL 或本地持久化存储。只有公开首页与服装详情提供分享；预约和回执页关闭分享入口。

服装图片继续来自后台上传目录，并转换为同一服务地址的完整 URL。没有实拍时显示“实拍待上传”，不把示意图当作实物。正式库不应导入示例顾客和示例预约。

## 验证与发布边界

```bash
npm test
npm run build
```

自动测试包括日期/价格、开发与正式域名边界、真实 Express/SQLite 接口下的无登录浏览、预约防连点、后台确认后回执刷新、错误手机号隔离、价格变更重新确认、以及页面文件/事件完整性。测试在临时数据库中运行，不写入门店数据。

本机已安装官方微信开发者工具 Stable 2.02.2608080，使用测试号与基础库 3.17.3 完成编译，检查了首页、服装目录、编号筛选、详情月历、预约表单和预约查询页。账号持有人确认手动点击可正常进入下一页；模拟器的自动点击存在兼容限制。经账号持有人明确确认，仅在本项目的私有配置中关闭了本地网络校验。`project.config.json` 的域名校验仍保持开启，本地覆盖位于 Git 忽略的 `project.private.config.json`，不应复制到发布环境。

电脑联调可使用 `http://127.0.0.1:3000`。本机忽略的 `config.js` 已连接现有、独立且限时的云端示例测试后台，并已生成约 54 KB 的开发版预览包；未改变服务器配置或公网规则。预览二维码有有效期，过期后需在开发者工具重新点击“预览”。测试后台到期后需停止使用该地址。手机预览是开发版调试，不代替正式账号、备案和 HTTPS 合法域名配置。

自动测试和本机模拟器检查不等于完整手机验收或平台审核。手机端已确认开发预览可加载云端示例服装目录，仍须继续验收实拍与月历、提交预约、后台确认、查询回执，检查 iOS/Android 页面与隐私设置；正式域名等发布条件就绪后再提审。当前已上传注册账号的开发版本，尚未提交正式审核或发布，也未改动云端服务、DNS、备案或正式库存。测试号和注册账号的 AppID 仅填入本地项目配置，未保存或使用 AppSecret。

营业前应按预计高峰做联调压测。现有预约接口按来源 IP 限制 30 次/小时；如果大量顾客共用门店 Wi-Fi/同一出口，需要根据实测调整限制策略，避免把顾客数量直接当作并发量。共用主机升级与否应结合原业务负载决定。营业结束后可关闭顾客预约入口并保留数据与备份；不能为停用季节业务关掉共用主机。
