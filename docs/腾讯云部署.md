# 腾讯云部署与版本发布

代码仓库：https://github.com/sr479/huashan 。以 `main` 保存可运行代码，使用 `v1.0.0` 形式的版本标签记录发布点。每次提交及拉取请求会运行 GitHub Actions 测试、类型检查、生产构建和镜像构建；检查通过后再部署指定标签。当前没有向云服务器自动发布的工作流，也不需要在 GitHub 保存服务器私钥或生产密码。

## 上线前核对

已有实例可以运行多个业务。先在目标 Linux 服务器执行只读检查：

```sh
sh deploy/preflight.sh
```

核对内存、磁盘、80/443/3300 端口、已有容器和反向代理。2 GB 内存的机器在同时构建镜像时也可能出现资源高峰；若已有业务重要、可用内存不足或需要分别重启维护，使用独立实例更合适。不要重装已有服务器，也不要停止其他业务。

运行环境为 Docker Engine 和 Docker Compose v2。Ubuntu 安装步骤以 [Docker 官方文档](https://docs.docker.com/engine/install/ubuntu/) 为准；若服务器已安装则继续使用现有环境。

为 `huashanjie.top` 配置指向目标公网 IP 的 `@` A 记录，核对备案接入状态。轻量应用服务器防火墙允许 TCP 80/443；SSH 仅允许必要来源。域名解析、放行端口和证书申请在确认部署目标后执行。参考 [腾讯云 DNS 解析](https://cloud.tencent.com/document/product/302/3446) 和 [轻量服务器防火墙](https://cloud.tencent.com/document/product/1207/44577)。

## 准备服务器目录

下面命令在目标服务器执行，目录和数据属于花山节独立项目：

```sh
sudo install -d -o "$USER" -g "$(id -gn)" /opt/huashanjie
git clone https://github.com/sr479/huashan.git /opt/huashanjie
cd /opt/huashanjie
sh deploy/configure.sh
```

配置脚本会生成新的随机管理员密码，将 `.env` 权限设为 600，遇到现有 `.env` 会停止，避免覆盖。请在服务器本地查看密码并妥善保存。部署配置强制关闭示例数据；本机的 `.env`、数据库和图片不会随 Git 复制。

Compose 项目名固定为 `huashanjie`，数据持久卷为 `huashanjie_store_data`。改变代码目录或版本不会改变数据库位置；不要执行 `docker compose down -v`。

## 方案一：与已有业务共用服务器

先完成只读检查。使用共用模式，仅启动花山节应用，将端口绑定到服务器本机回环地址：

```sh
sh deploy/release.sh v1.0.0 shared
curl -fsS http://127.0.0.1:3300/api/health
```

此模式不会启动项目内的 Caddy。继续使用原有 Nginx/Caddy，以域名 `huashanjie.top` 将 HTTPS 请求转发到 `127.0.0.1:3300`，公网不放行 3300 端口。若 3300 已占用，先修改 `.env` 的 `APP_BIND_PORT` 和反向代理的目标端口。

共用模式将应用限制为 0.75 核 CPU、512 MB 内存、128 个进程，日志最多保留 3 个 10 MB 文件。容量增加后可按实际情况调整。

从 v1.0.1 开始，可在构建机器使用 `docker buildx build --platform linux/amd64 --build-arg VCS_REF=<版本完整提交号> --load -t huashanjie:v1.0.1 .` 生成与服务器架构一致的镜像。将镜像包传至服务器并执行 `docker load` 后，运行 `sh deploy/release.sh v1.0.1 shared --prebuilt`。脚本会检查镜像中的提交号与版本标签一致，不在服务器进行编译。

- 已有宿主机 Nginx：使用 `deploy/nginx.conf.example` 作为新站点配置，填写实际证书路径。证书准备就绪后先执行 `sudo nginx -t`，通过后仅 reload。现有站点配置保持原样。
- 已有宿主机 Caddy：在其现有配置加入 `huashanjie.top { reverse_proxy 127.0.0.1:3300 }`，按已有服务的方式校验和 reload。
- 原有代理也在容器中：容器内的 `127.0.0.1` 指向该容器自身。应先检查原有 Docker 网络，再配置连通路径，不能直接套用宿主机代理示例。

代理必须保留 `Host` 并正确传递 `X-Forwarded-Proto`。应用使用 HTTPS Secure Cookie；本机 HTTP 健康接口可测试，但管理员须通过最终 HTTPS 域名登录。

## 方案二：独立实例，或确认 80/443 没有其他服务

```sh
sh deploy/release.sh v1.0.0 standalone
```

同时启动应用与 Caddy，Caddy 在域名解析和端口正确时申请 HTTPS 证书。不要在已有服务占用 80/443 的服务器上运行该模式。数据、图片和证书均使用独立持久卷。

## 验收与备份

上线后检查：

1. `https://huashanjie.top/`、`/admin` 和 `/api/health` 正常，后台直接刷新可访问。
2. 首次登录使用服务器 `.env` 的管理员账号和密码。
3. 填写实际门店电话、地址、营业时间、备案号及租赁规则，录入真实服装实拍与价格。
4. 完整跑通预约、确认、收取租金与押金、取衣、归还验收、退押金、结算和清洗，检查同一套服装不会重复确认。
5. 生成数据库与图片备份，并另存到不同磁盘或对象存储。

```sh
docker compose exec -T app npm run backup
docker compose ps
docker compose logs --tail=100 app
```

`deploy/backup.service` 和 `deploy/backup.timer` 是每日备份模板，尚未安装或启用。启用前核对 `/opt/huashanjie` 和 Docker 路径，避免修改其他业务的定时任务。

## 后续更新与回退

开发在功能分支进行，经过检查后合并至 `main`；提交信息使用中文。发布时更新 `CHANGELOG.md` 和项目版本，建立并推送新的 `vX.Y.Z` 标签。服务器重新执行 `release.sh`，传入标签和原部署模式。脚本会拒绝未提交的代码修改，防止并发部署，并在已有应用运行时先生成备份。

脚本只负责花山节项目的容器，不改 DNS、防火墙或原有代理。构建失败时请检查输出；已运行的旧容器不会因构建命令而停止。启动失败可能已替换应用容器，需要检查 `docker compose ps` 与日志，并按之前记录的标签重新部署。不要移动旧标签或强制推送 `main`。

代码回退可以重新部署旧标签。涉及数据库结构升级时，先核对兼容性；必要时停止花山节应用，从升级前备份恢复数据库和图片后再启动。保留原数据副本，不直接覆盖正在使用的 SQLite。
